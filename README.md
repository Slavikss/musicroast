# 🔥 MusicRoast

Сервис прожарки музыкального вкуса. Забирает библиотеку из Яндекс Музыки,
сам считает по ней статистику (топ-артисты, жанры, «застрял в 2016», запойные
дни, залётный шансон) и скармливает эти **факты** Gemini — поэтому прожарка
получается не абстрактной, а бьёт по конкретным цифрам, именам и датам.

## Что умеет

- **🩺 Детерминированное диагноз-ядро**: для библиотеки лайков сервис тянет
  минимальный набор данных (лайки, чарт, pins+плейлисты, дизлайки, лирика)
  и считает пять осей — концентрация (HHI по артистам), обскурность
  (пересечение с чартом + слушатели артистов), разрыв «заявленное vs
  фактическое», тренд затухания, лицемерие (дизлайкнутое ∩ лайкнутое).
  Агрегатор — **argmax, не среднее**: ровно один архетип на снапшот
  («Крепостной одного артиста», «Позёр», «Некроз вкуса», «Дитя алгоритма»,
  «Археолог-сноб», «Двуличный меломан», «Склад без вывески») + 3 трека-улики.
  Гейты: ≥200 лайков, ≥12 мес истории, ≥3 улики, покрытие текстов ≥60% для
  лирик-слоя; провал гейтов = мягкая деградация в обычную прожарку.
  Снапшот хешируется — тот же снапшот даёт тот же диагноз бесплатно, а
  append-only реестр диагнозов даёт дифф во времени («с прошлого раза
  диагноз только усугубился»). LLM в аналитическом пути не участвует —
  он получает готовый архетип и только рендерит приговор.
- **Три уровня прожарки**: 🌤 лёгкая (друг подкалывает за пивом) → 🔥 средняя
  (стендап-тролль) → ☠️ кремация (вскрытие вкуса с оглашением результатов).
- **Оценка вкуса**: каждый роаст заканчивается вердиктом — балл N/10, диагноз
  одной фразой и «топ позора» из трёх фактов.
- **🖼 Обложка позора** — генерация изображения по тексту прожарки.
- **⚔️ Батлы**: вызови друга по ссылке/коду, Gemini сравнит ваши библиотеки
  и объявит, чей вкус позорнее (при отказе судьи бой резолвится по очкам).
- **Виральный шеринг**: после прожарки — форвардабельная карточка со счётом
  и deep-link. Друг по ссылке видит только тизер («вкус 3.2/10, диагноз …» +
  первый панч, остальное под ▒▒▒) — полный текст и вердикт «чей вкус хуже»
  открываются после его собственной прожарки, а вам обоим прилетает авто-батл.
- **Интерфейсы**: Telegram-бот + веб-страница на `/` (vanilla JS, тёмная тема).

## Как пользователь получает токен

Основной путь — **OAuth Device Flow** (без копирования URL, работает с телефона):

1. Жми «🔑 Войти в Яндекс» в боте (или «Войти через Яндекс» на веб-странице).
2. Сервис показывает код и кнопку «Открыть Яндекс».
3. Входишь в аккаунт, вводишь код — сервис сам замечает подтверждение,
   валидирует токен и здоровается по имени с числом лайкнутых треков.

Запасной путь: открыть [OAuth-ссылку](https://oauth.yandex.ru/authorize?response_type=token&client_id=23cabbbdc6cd418abb4b39c32c41195d),
авторизоваться и прислать боту адрес страницы после редиректа (или сам токен
`y0_...`) — парсер понимает любой формат. Логин и пароль сервису не нужны никогда.

Токены живут в памяти процесса с TTL; при наличии `refresh_token` протухший
access_token обновляется автоматически.

## Запуск

```bash
cp .env.example .env   # заполни GOOGLE_API_KEY и TELEGRAM_BOT_TOKEN
poetry install
poetry run uvicorn main:app --host 0.0.0.0 --port 8000
```

`APP_MODE=both` (дефолт) поднимает REST API и Telegram-бота в одном процессе —
это обязательно для батлов и шеринга между ботом и вебом. Веб-интерфейс:
`http://localhost:8000/`.

### Прогон без реального аккаунта Яндекса (mock-режим)

```bash
MOCK_STREAMING=1 poetry run uvicorn main:app
```

Любой токен-подобный ввод (например `y0_mocktoken_aaaaaaaaaaaaaaaaaaaa`)
обслужит встроенная «прожариваемая» библиотека: перекос по Кино, кластер
2016–2017, запойный день, залётный шансон. Нужен только `GOOGLE_API_KEY`.

### Docker

```bash
docker build -t musicroast .
docker run --rm -p 8000:8000 --env-file .env musicroast
```

### Тесты

```bash
poetry run pytest
```

Тесты офлайновые: Gemini и Яндекс замоканы.

## API

| Метод | Роут | Что делает |
|---|---|---|
| GET | `/` | Веб-интерфейс |
| POST | `/auth/device/start` | Запуск OAuth Device Flow → `{session_id, verification_url, user_code}` |
| GET | `/auth/device/{session_id}` | Статус: `pending / ready / expired` (+токен и аккаунт при `ready`) |
| POST | `/auth/validate` | Парсинг и валидация вставленного URL/токена |
| GET | `/auth/yandex/url` | OAuth-ссылка для ручного флоу |
| POST | `/streaming/playlists` | Список плейлистов |
| POST | `/streaming/playlist-info` | Треки плейлиста |
| POST | `/roast` | Прожарка: `{roast, score, diagnosis, shame_facts, stats, roast_id, taste_diagnosis?, gate_status?, image_url?}` |
| GET | `/roast/{roast_id}/teaser` | Тизер для шеринга (счёт + диагноз + первый панч) |
| POST | `/battle/start` | Создать батл → `{code}` |
| POST | `/battle/join` | Присоединиться и получить вердикт |
| GET | `/battle/{code}` | Статус/результат батла |

## Архитектура

```
app/
├── __init__.py            # FastAPI-приложение, lifespan поднимает бота
├── bot.py                 # aiogram-бот: device flow, уровни, батлы, шеринг
├── config.py              # env-конфиг
├── token_storage.py       # in-memory токены с TTL и авто-рефрешем
├── prompts/manager.py     # промпты уровней + батла, контракт ===VERDICT===
├── services/
│   ├── music_roast.py     # оркестратор: snapshot → diagnose → roast → battle
│   ├── diagnosis.py       # детерминированное ядро: 5 осей, гейты, argmax
│   ├── diagnosis_registry.py # append-only журнал диагнозов (дифф во времени)
│   ├── lyrics_layer.py    # лирик-слой за гейтом покрытия ≥60%
│   ├── library_stats.py   # вычисление фактов по библиотеке
│   ├── gemini.py          # Gemini: текст, вердикт-парсер, картинки, safety
│   ├── device_auth.py     # OAuth Device Flow менеджер (бот + веб)
│   ├── battle.py          # реестр батлов (коды, TTL)
│   └── roast_registry.py  # реестр прожарок для deep-link'ов и тизеров
├── streaming/             # Яндекс (реализовано), mock, заглушки Spotify/Apple
└── utils/                 # парсер токенов, markdown→HTML, сплит для Telegram
```

Состояние (токены, батлы, прожарки) — in-memory с TTL: сервис рассчитан на
один процесс (`APP_MODE=both`); при рестарте всё обнуляется.

PromptManager поддерживает версионирование и оверрайд промптов через JSON
(`PROMPT_CONFIG_PATH`). Переменные окружения — в `.env.example`.
